## 3. 원인 (측정된 근거)

### 3-1. 카페 단계는 기본이 꺼짐이고, 켜진 흔적이 없음

`scripts/run-scheduled-pipeline.mjs`는 라운지 등록까지 끝난 뒤 이렇게 갈립니다.

```js
const cafe = normalizeCafePublisherConfig(config, rootDir);
if (!cafe.enabled) {
  console.log("Cafe publisher is disabled; replay automation finished without a Cafe write.");
  return;
}
```

그런데 Git에 추적되는 `make-youtube-automation/config.windows.json`에는
**`cafePublisher` 블록 자체가 없습니다.** 없으면 `enabled=false`로 계산되어 위에서 그대로 종료됩니다.
블록이 있는 건 `config.example.json`뿐이고 그마저 `enabled:false, mode:"dry", notify:false`입니다.

### 3-2. 8/20 설정 분리 이후 예약 작업 재등록이 필요한 상태

커밋 `9359bea`(8/20 15:51)에서 운영 설정을 Git 밖 `config.local.json`으로 빼도록 바꿨습니다.
그런데 예약 작업이 그 파일을 쓰려면 아래로 **재등록**해야 합니다.

```powershell
.\scripts\install-windows.ps1 -Config config.local.json
```

재등록하지 않았다면 기존 작업은 `-Config` 없이 실행되고,
`invoke-scheduled.ps1`의 기본값인 `config.windows.json`(= 카페 블록 없는 추적 파일)을 읽습니다.

### 3-3. 운영 전환 7단계가 완료된 흔적 없음

navercafe README의 운영 전환 순서 7단계는
"게시글 읽기 검증과 Telegram 전송까지 한 번 통과한 뒤 예약 설정을 `mode=publish`, `notify=true`로 바꾼다"입니다.
MF 텔레그램방에 **카페 발행 알림이 한 번도 온 적이 없습니다.** 이 게이트를 통과한 적이 없다는 뜻입니다.
