| | |

| **가장 큰 반대 근거** | PLAUD Unlimited도 **하루 24시간 상한**이 있습니다. 라이브 53.6시간이면 최소 3일, 일상 사용분과 겹치면 4~5일입니다. 급하면 라이브도 로컬로 돌려야 합니다 |
| **승인 시** | 쇼츠·일반영상 794편은 오늘 밤 로컬로 끝납니다. 라이브 50편은 기존 파이프라인에 URL만 넣으면 3~4일 무인 |

**실행 위치**: **맥북**. 윈도우 PC는 이 작업에 한해 역효과입니다 (5장).

## 1. 실측: 유튜브 자막 vs 로컬 whisper

테스트 영상: 「1년 안에 디자이너는 사라질까?」 (`XQf8hqFBmk4`, 16분 08초, 다화자 대담)

| 항목 | 유튜브 자동자막 | 로컬 whisper large-v3-turbo |
|---|---|---|
| 확보 시간 | 4초 | 다운로드 3초 + 변환 7초 + 전사 26초 |
| 글자수 | 8,012 | 7,561 |
| 비용 | 0원 | 0원 |

### 같은 구간 비교 (굵은 곳이 차이)

**유튜브 자막**
> 글씨의 **가족성**들이 너무 떨어지고 너무 줄글처럼 되어 있어서 디자인적 요소가 크게 **감이되어** 있어 보이지 않는게 조금 아쉬운 부분인 거 같다. **작간 행간**이 제대로 되어 있지 않고 **가족성**이 떨어져서…

**whisper**
> 우선 글씨의 **가독성**들이 너무 떨어지고 너무 줄글처럼 되어 있어서 디자인적 요소가 크게 **가미되어** 있어 보이지 않는 게 조금 아쉬운 부분인 것 같다. 그냥 작은 행간이 제대로 되어 있지 않고 **가독성**이 떨어져서…

또 다른 구간:

| 실제 표현 | 유튜브 자막 | whisper |
|---|---|---|
| 상세 페이지 | **상색 페이지** | 상세 페이지 |
| 인간 고유의 스킬 | 인간 고유의 스킬 | 인간 고유의 스킬풀 |
| (화자 전환) | `>>` 마커가 본문에 섞여 들어감 | 화자 구분 없음 |

### 판정

- **whisper가 명확히 낫습니다.** 유튜브 자막은 "가독성"을 전편에 걸쳐 "가족성"으로 틀리는 식의 **일관된 용어 오류**를 냅니다. 검색·인용·전자책 어디에 써도 문제가 됩니다.
- whisper도 완벽하진 않습니다. 고유명사(브랜드명·사람 이름)에서 헛도는 구간이 있고, "스킬풀" 같은 어미 붙임이 나옵니다. 다만 **문장이 무너지지는 않습니다.**
- **유튜브 자막은 버리지 말고 대조용으로 보관**합니다. 두 결과가 크게 다른 구간이 곧 "사람이 확인해야 할 구간"입니다. 공짜로 얻는 품질 검사기입니다.

## 2. 오디오 규격 — "음질 좋지만 용량 작게"의 정답

**결론: 16kHz 모노 / opus 24kbps.**

whisper는 입력을 무조건 **16kHz 모노**로 다운샘플한 뒤 처리합니다.
따라서 48kHz 스테레오 128kbps로 받아도 정확도는 **1도 안 오르고** 용량만 5배가 됩니다.

실측 (16분 영상):

| 형식 | 용량 | 86시간 환산 |
|---|---:|---:|
| 원본 webm 오디오 | 14.1 MB | 약 4.5 GB |
| **16kHz 모노 opus 24k** | **2.9 MB** | **약 940 MB** |

라이브 50편(53.6시간)만 받으면 약 580MB입니다. 윈도우로 옮기든 zip으로 묶든 부담이 없습니다.

```bash
# 다운로드 + 변환 (한 줄)
yt-dlp -f bestaudio -o "%(id)s.%(ext)s" "<URL>"
ffmpeg -i <입력> -ac 1 -ar 16000 -c:a libopus -b:a 24k <id>.opus
```

참고로 민수님이 PLAUD에 올리실 때 쓰신 `48kbps mono`도 나쁘지 않지만, 로컬 whisper 기준으로는 24kbps로 절반을 더 줄여도 결과가 같습니다.

## 3. PLAUD를 쓸 것인가 — v2에서 뒤집습니다

v2에서 "제외"로 판정했는데 **틀렸습니다.** 민수님 지적대로 확인해 보니 두 전제가 다 어긋나 있었습니다.

### 확인 결과

| v2에서 쓴 전제 | 실제 |
|---|---|
| "CLI가 읽기 전용이라 업로드 자동화 불가" | `plaud` CLI는 맞지만, **확장 서버에 별도 업로드 경로가 이미 있습니다** — `server/plaud/extension-upload.js` (852줄) |
| "844편을 손으로 올려야 함" | `POST /plaud/send`에 **URL만 던지면 끝**입니다. 손 안 갑니다 |
| "분당 과금 13만~19만원" | 구독 중이라 **0원**. 최근 30일 **119.4시간 / 99건** 처리 실측 → Pro(20시간·월)로는 불가능하므로 **Unlimited 확정** |

### 기존 파이프라인이 이미 하는 일

```text
POST /plaud/send  { url }
  → yt-dlp 오디오 다운로드 (쿠키 자동 감지, 403 시 쿠키 없이 재시도)
  → 5시간 초과분 자동 분할 (4.5시간 단위)
  → 64kbps 압축, 480MB 업로드 상한 준수
  → PLAUD 웹 업로드 (헤드리스 — 화면·커서 안 뺏음)
  → 전사 생성 대기 → 전사본 export
  → 분할본 병합 → 인사이트 프로세서 연결
  → 실패분은 큐에 남고 /plaud/retry-failed 로 재다운로드 없이 재시도
```

민수님이 이미 만들어 두신 게 제가 새로 설계하려던 것보다 완성도가 높습니다. **새로 만들 게 없습니다.**

### 그래도 전량 PLAUD는 반대합니다

| 구분 | 편수 | 분량 | 권장 | 이유 |
|---|---:|---:|---|---|
| 쇼츠 | 649 | 5.4시간 | **로컬 whisper** | 편당 30초. 업로드 세션 오버헤드가 콘텐츠보다 큽니다. 브라우저 세션 649번 = **실패 지점 649개** |
| 일반 영상 | 145 | 27.5시간 | **로컬 whisper** | 대부분 단일 화자·짧은 영상. 화자분리 실익이 낮습니다 |
| **라이브** | **50** | **53.6시간** | **PLAUD** | 다화자·수강생 Q&A·고가치. **화자분리 + 요약 + 인사이트 회수**가 여기서만 값어치를 합니다 |

### 처리 시간 비교

| 경로 | 라이브 53.6시간 | 전체 86시간 |
|---|---|---|
| PLAUD (Unlimited, 하루 24시간 상한) | **3일** (일상 사용분 겹치면 4~5일) | 5~7일 |
| 로컬 whisper (37배 실시간) | 1.4시간 | 2.3시간 |

**하루 24시간 상한이 유일한 제약**입니다. 급하지 않으면 라이브는 PLAUD가 낫고, 급하면 로컬로 돌린 뒤 화자분리만 나중에 붙이면 됩니다.

### 먼저 할 일: 1편 비교

라이브 1편을 **PLAUD와 로컬 whisper 양쪽에 넣고 결과를 나란히** 봅니다.
둘 다 0원이고 30분이면 판명됩니다. 이걸 보고 라이브 50편의 경로를 확정합니다.

- 볼 것: 한국어 정확도, 화자분리가 실제로 쓸 만한지, 강사·수강생 구분이 되는지
- 안 보고 정하면 3일짜리 배치를 잘못된 쪽에 걸게 됩니다

## 4. 멤버십 라이브 오디오 — 유일한 난관

자막이 아니라 **오디오**가 필요해지면서 v1의 "공식 API로 자막 받기" 경로는 이 구간에 못 씁니다.
API는 자막만 주지 오디오를 주지 않습니다. 로그인이 반드시 필요합니다.

기존 파이프라인은 이미 `--cookies-from-browser`로 회원전용 영상을 처리하고 있습니다.
즉 **동작은 이미 되고**, 남은 건 어느 계정 쿠키를 쓰느냐입니다.

| 경로 | 채널 제재 위험 | 손이 가는 정도 | 판정 |
|---|---|---|---|
| **멤버십 가입한 별도 계정 쿠키 + yt-dlp** | **채널과 분리됨** | 무인 | **1순위** |
| YouTube Studio 공식 다운로드 | 없음 | 50편 수작업 클릭 | 2순위 |
| 채널 소유 계정 쿠키 + yt-dlp | 낮지만 **결과가 치명적** | 무인 | 피함 |

### 계정 분리가 핵심입니다

v1에서 GPT가 지적한 위험은 "**소유 계정**으로 자동 접근하는 것"이었습니다.
그런데 이건 우회할 수 있습니다.

**회사가 자기 채널 멤버십에 서브 계정 하나를 가입시키면 됩니다.** 월 몇천 원입니다.

- 그 계정으로 로그인한 전용 크롬 프로필에서만 yt-dlp를 돌립니다
- 최악의 경우 제재당하는 건 **그 서브 계정 하나**이고, 채널·소유 계정·수익화는 무사합니다
- 멤버십 영상 접근 권한은 소유자든 구독자든 동일하므로 결과물은 같습니다

여기에 보수적 실행 규칙을 얹습니다.

- 편당 5~10초 간격 (`--sleep-interval 5 --max-sleep-interval 10`)
- 오디오만 (`-f bestaudio`), 영상 스트림은 받지 않음
- 하루 25편씩 이틀에 나눠서
- 403이 뜨면 자동 재시도하지 않고 **멈추고 보고**

### 확인된 사실

원본 파일이 어딘가 남아 있으면 다운로드 자체가 필요 없는데, **찾아봤지만 없습니다.**
`make-youtube-automation/downloads`는 비어 있고, 윈도우 PC의 `LiveReplay` 폴더에도 영상 파일이 없습니다.

## 5. 실행 위치 — 맥북 vs 윈도우 PC

민수님 직관("서버처럼 쓰는 윈도우에 던져두면 알아서 끝나 있을 것")은 **일반적으로는 맞지만, 이 작업에서는 반대**입니다.

| | 맥북 | 24시간 윈도우 PC |
|---|---|---|
| 칩 | **Apple M5 Pro / 48GB** | AMD Ryzen 5 2400G (2018, 4코어) / 14GB |
| GPU 가속 | **Metal 사용** | CUDA 없음. Vega 11 내장그래픽은 whisper에 무의미 |
| 실측 전사 속도 | **37배 실시간** (16분 → 26초) | 미실측. CPU 전용이라 자릿수 단위로 느림 |
| 86시간 전사 예상 | **2.3시간** | 며칠 단위 |

**맥북에서 2.3시간이면 끝납니다.** 백그라운드로 돌리면 되고, whisper.cpp는 스레드 수를 제한할 수 있어(`-t 6`) 민수님이 쓰시는 데 방해되지 않게 조절 가능합니다.

### 윈도우 PC를 안 쓴다는 뜻은 아닙니다

역할을 나누는 게 맞습니다.

- **윈도우 PC**: 오디오 다운로드(CPU를 안 씀, 시간만 걸림), 야간 스케줄, 원본 보관. 이미 라이브 재업로드 자동화가 거기 살고 있어 자연스럽습니다
- **맥북**: 전사(GPU 가속이 결정적)

다만 다운로드도 16분 영상에 3초라 844편이 1~2시간이면 끝납니다. 굳이 나눌 실익이 크지 않으면 **맥에서 통으로 돌리는 게 단순합니다.**

## 6. 확장프로그램 활용

**서버 엔진을 그대로 씁니다.** 이미 필요한 게 다 있습니다.

| 이미 있는 것 | 파일 |
|---|---|
| yt-dlp 래핑 + 쿠키 자동 감지 + 403 재시도 | `server/server.js` |
| PLAUD 업로드 전 과정 | `server/plaud/extension-upload.js` |
| 5시간 자동 분할 / 전사본 병합 | `plaud/audio-split.js`, `plaud/transcript-merge.js` |
| 실패 큐 + 재다운로드 없는 재시도 | `POST /plaud/retry-failed` |
| 인사이트 회수 | `plaud/insight-processor.sh` |

**추가할 것은 두 개뿐입니다.**

1. **배치 러너** — 영상 URL 목록을 받아 `POST /plaud/send`에 순차로 넣고, 실패분을 재시도 큐로 넘기는 스크립트
2. **로컬 whisper 분기** — 쇼츠·일반영상은 PLAUD를 거치지 않고 `bestaudio → 16kHz 모노 opus → whisper-cli`로 바로 전사하는 경로

확장프로그램 **UI는 쓰지 않습니다.** 영상 하나씩 버튼 클릭 방식이라 844편에는 맞지 않습니다.
UI가 아니라 **엔진 재사용**입니다.

## 7. 산출물 구조

**zip에는 전사 파일만 담습니다.** 오디오·원본·중간 산출물은 로컬에만 두고 전달하지 않습니다.

```text
메이크패밀리-전사.zip
├── README.md                      # 무엇이 들어있는지, 어떻게 읽는지
├── 목록.csv                        # 844행: 제목·날짜·길이·유형·공개등급·전사방식
└── 전사/
    ├── 일반영상/{날짜}_{제목}_{video_id}.md
    ├── 쇼츠/{날짜}_{제목}_{video_id}.md
    └── 라이브/{날짜}_{제목}_{video_id}.md
```

로컬에만 남기고 zip에서 빼는 것:

| 항목 | 이유 |
|---|---|
| 오디오 파일 (약 1GB) | 전달 목적이 아님. 재전사가 필요하면 다시 받으면 됨 |
| 유튜브 자동자막 원본 | 내부 품질 검사용. 오류가 섞여 있어 오히려 혼선 |
| PLAUD 요약·액션아이템 | 필요하면 별도 요청 시 추가 |

각 md 프론트매터:

```yaml
video_id: XQf8hqFBmk4
title: 1년 안에 디자이너는 사라질까?

published: 2026-06-16
type: video | shorts | live
access_tier: public | members_only
reuse_policy: open | internal_only
duration_sec: 968
source: whisper_large_v3_turbo
pii_status: unreviewed | masked
```

### zip으로 전달하기 전에 반드시 볼 것

| 항목 | 왜 |
|---|---|
| `access_tier: members_only` | 멤버십 전용 라이브 내용을 무료 전자책·블로그로 그대로 내보내면 **유료 멤버십의 가치가 무너집니다.** 상철님께 넘길 때 이 구분이 파일 안에 있어야 합니다 |
| 수강생 실명·연락처 | 라이브 Q&A에 섞여 있습니다. 로컬 정규식 마스킹 후 전달 |
| 전달 경로 | zip은 사내 공유만. 외부 클라우드·깃허브에 올리지 않습니다 |
