1. 실측: 유튜브 자막 vs 로컬 whisper

테스트 영상: 「1년 안에 디자이너는 사라질까?」 (XQf8hqFBmk4, 16분 08초, 다화자 대담)

항목 유튜브 자동자막 로컬 whisper large-v3-turbo
확보 시간 4초 다운로드 3초 + 변환 7초 + 전사 26초
글자수 8,012 7,561
비용 0원 0원

같은 구간 비교 (굵은 곳이 차이)

유튜브 자막

글씨의 가족성들이 너무 떨어지고 너무 줄글처럼 되어 있어서 디자인적 요소가 크게 감이되어 있어 보이지 않는게 조금 아쉬운 부분인 거 같다. 작간 행간이 제대로 되어 있지 않고 가족성이 떨어져서…

whisper

우선 글씨의 가독성들이 너무 떨어지고 너무 줄글처럼 되어 있어서 디자인적 요소가 크게 가미되어 있어 보이지 않는 게 조금 아쉬운 부분인 것 같다. 그냥 작은 행간이 제대로 되어 있지 않고 가독성이 떨어져서…

또 다른 구간:

실제 표현 유튜브 자막 whisper
상세 페이지 상색 페이지 상세 페이지
인간 고유의 스킬 인간 고유의 스킬 인간 고유의 스킬풀
(화자 전환) >> 마커가 본문에 섞여 들어감 화자 구분 없음

판정

  • whisper가 명확히 낫습니다. 유튜브 자막은 "가독성"을 전편에 걸쳐 "가족성"으로 틀리는 식의 일관된 용어 오류를 냅니다. 검색·인용·전자책 어디에 써도 문제가 됩니다.
  • whisper도 완벽하진 않습니다. 고유명사(브랜드명·사람 이름)에서 헛도는 구간이 있고, "스킬풀" 같은 어미 붙임이 나옵니다. 다만 문장이 무너지지는 않습니다.
  • 유튜브 자막은 버리지 말고 대조용으로 보관합니다. 두 결과가 크게 다른 구간이 곧 "사람이 확인해야 할 구간"입니다. 공짜로 얻는 품질 검사기입니다.

2. 오디오 규격 — "음질 좋지만 용량 작게"의 정답

결론: 16kHz 모노 / opus 24kbps.

whisper는 입력을 무조건 16kHz 모노로 다운샘플한 뒤 처리합니다.
따라서 48kHz 스테레오 128kbps로 받아도 정확도는 1도 안 오르고 용량만 5배가 됩니다.

실측 (16분 영상):

형식 용량 86시간 환산
원본 webm 오디오 14.1 MB 약 4.5 GB
16kHz 모노 opus 24k 2.9 MB 약 940 MB

라이브 50편(53.6시간)만 받으면 약 580MB입니다. 윈도우로 옮기든 zip으로 묶든 부담이 없습니다.

# 다운로드 + 변환 (한 줄)
yt-dlp -f bestaudio -o "%(id)s.%(ext)s" "<URL>"
ffmpeg -i <입력> -ac 1 -ar 16000 -c:a libopus -b:a 24k <id>.opus

참고로 민수님이 PLAUD에 올리실 때 쓰신 48kbps mono도 나쁘지 않지만, 로컬 whisper 기준으로는 24kbps로 절반을 더 줄여도 결과가 같습니다.

3. PLAUD를 쓸 것인가 — v2에서 뒤집습니다

v2에서 "제외"로 판정했는데 틀렸습니다. 민수님 지적대로 확인해 보니 두 전제가 다 어긋나 있었습니다.

확인 결과

v2에서 쓴 전제 실제
"CLI가 읽기 전용이라 업로드 자동화 불가" plaud CLI는 맞지만, 확장 서버에 별도 업로드 경로가 이미 있습니다 — server/plaud/extension-upload.js (852줄)
"844편을 손으로 올려야 함" POST /plaud/send에 URL만 던지면 끝입니다. 손 안 갑니다
"분당 과금 13만~19만원" 구독 중이라 0원. 최근 30일 119.4시간 / 99건 처리 실측 → Pro(20시간·월)로는 불가능하므로 Unlimited 확정

기존 파이프라인이 이미 하는 일

POST /plaud/send  { url }
  → yt-dlp 오디오 다운로드 (쿠키 자동 감지, 403 시 쿠키 없이 재시도)
  → 5시간 초과분 자동 분할 (4.5시간 단위)
  → 64kbps 압축, 480MB 업로드 상한 준수
  → PLAUD 웹 업로드 (헤드리스 — 화면·커서 안 뺏음)
  → 전사 생성 대기 → 전사본 export
  → 분할본 병합 → 인사이트 프로세서 연결
  → 실패분은 큐에 남고 /plaud/retry-failed 로 재다운로드 없이 재시도

민수님이 이미 만들어 두신 게 제가 새로 설계하려던 것보다 완성도가 높습니다. 새로 만들 게 없습니다.

일반영상을 로컬로 돌리는 이유는 속도가 아니라 쿼터 보존입니다.
27.5시간을 PLAUD에 태우면 하루 반을 더 쓰게 되고, 그만큼 민수님 녹음 여유가 줄어듭니다.

최장 1편이 1.87시간이라 5시간 분할 로직에는 걸리지 않습니다. 최단은 30.9분입니다.

다만 "18시간 고정"은 바꿔야 합니다

민수님 개인 PLAUD 사용량을 최근 30일로 실측했습니다.
일평균 4.6시간
최대 20.4시간 (2026-07-25)
6시간 초과한 날 26일 중 7일 (27%)

18시간을 고정으로 잡으면 여유가 6시간뿐인데, 그 여유를 넘긴 날이 4일에 1일꼴입니다.
겹치는 날에는 24시간 상한에 걸려 민수님 회의·컨설팅 녹음이 밀립니다. 그게 훨씬 큰 손해입니다.

러너 설계: 고정이 아니라 적응형

매일 배치 시작 전:
  1. plaud today 로 당일 사용량 U 측정
  2. 오늘 넣을 양 = min(18시간, 21시간 - U)      # 3시간은 항상 비워 둠
  3. 그만큼만 큐에서 꺼내 투입
  4. 남은 건 다음 날로 이월
  • 민수님이 많이 쓴 날은 알아서 적게 넣고 물러납니다
  • 3일이 4~5일로 늘어날 수 있지만, 민수님 녹음이 막히는 일은 없습니다
  • 실패분은 기존 POST /plaud/retry-failed 큐로 넘겨 재다운로드 없이 재시도합니다

참고: "Unlimited = 하루 24시간"은 요금제 비교 자료에서 확인한 값이고 공식 문서로 직접 검증하진 못했습니다.
위 설계는 실제 상한이 다르더라도 당일 사용량을 재서 물러나는 구조라 그대로 안전합니다.

판정: PLAUD > whisper > 유튜브 자막

whisper가 PLAUD보다 14% 적게 받아적었습니다. 처음엔 잘림을 의심했는데, whisper도 16분 05초까지 정상 커버했습니다.
차이는 겹쳐 말하는 구간입니다. 4명이 동시에 말할 때 단일 스트림 whisper는 하나만 받아적고, 화자분리 기반인 PLAUD는 각각을 잡아냅니다.

이건 다화자 콘텐츠에서 구조적으로 생기는 격차입니다. 전자책 원본으로 쓸 자료에서 14% 누락은 작지 않습니다.

그래서 일반영상 145편도 PLAUD로 보낼 것을 권합니다

v4에서 "일반영상은 로컬 whisper"로 잡았는데, 채널 콘텐츠가 인터뷰·대담 중심입니다.
「10년 의류 쇼핑몰 접고 죽은 꽃 팔기 시작한 이유 | 그리밋」처럼 게스트가 있는 포맷이 많고, 방금 테스트한 영상도 일반영상 탭에 있던 4인 대담입니다.

안 PLAUD 분량 소요 얻는 것 / 잃는 것
A. 194편 전부 PLAUD 81.1시간 약 5일 전량 화자분리 + 최고 정확도 / 이틀 더
B. 라이브만 PLAUD (v4안) 53.6시간 3일 + 로컬 45분 이틀 빠름 / 일반영상 145편에서 겹말 누락

A를 권합니다. 목적이 전자책·가이드북 원본이고 비용은 어느 쪽이든 0원입니다. 이틀 더 기다리는 값으로는 쌉니다.
급하시면 B로 가고, 나중에 일반영상만 다시 돌려도 됩니다.

실행 속도 참고

16분 오디오에 wall clock 약 3분 — 오디오 길이의 약 1/5입니다.
하루 18시간 배치면 실제 실행은 3~4시간이고 나머지는 쿼터 리셋 대기입니다.

4. 멤버십 라이브 오디오 — 유일한 난관

자막이 아니라 오디오가 필요해지면서 v1의 "공식 API로 자막 받기" 경로는 이 구간에 못 씁니다.
API는 자막만 주지 오디오를 주지 않습니다. 로그인이 반드시 필요합니다.

기존 파이프라인은 이미 --cookies-from-browser로 회원전용 영상을 처리하고 있습니다.
즉 동작은 이미 되고, 남은 건 어느 계정 쿠키를 쓰느냐입니다.

경로 채널 제재 위험 손이 가는 정도 판정
멤버십 가입한 별도 계정 쿠키 + yt-dlp 채널과 분리됨 무인 1순위
YouTube Studio 공식 다운로드 없음 50편 수작업 클릭 2순위
채널 소유 계정 쿠키 + yt-dlp 낮지만 결과가 치명적 무인 피함

계정 분리가 핵심입니다

v1에서 GPT가 지적한 위험은 "소유 계정으로 자동 접근하는 것"이었습니다.
그런데 이건 우회할 수 있습니다.

회사가 자기 채널 멤버십에 서브 계정 하나를 가입시키면 됩니다. 월 몇천 원입니다.

  • 그 계정으로 로그인한 전용 크롬 프로필에서만 yt-dlp를 돌립니다
  • 최악의 경우 제재당하는 건 그 서브 계정 하나이고, 채널·소유 계정·수익화는 무사합니다
  • 멤버십 영상 접근 권한은 소유자든 구독자든 동일하므로 결과물은 같습니다

여기에 보수적 실행 규칙을 얹습니다.

  • 편당 5~10초 간격 (--sleep-interval 5 --max-sleep-interval 10)
  • 오디오만 (-f bestaudio), 영상 스트림은 받지 않음
  • 하루 25편씩 이틀에 나눠서
  • 403이 뜨면 자동 재시도하지 않고 멈추고 보고

확인된 사실

원본 파일이 어딘가 남아 있으면 다운로드 자체가 필요 없는데, 찾아봤지만 없습니다.
make-youtube-automation/downloads는 비어 있고, 윈도우 PC의 LiveReplay 폴더에도 영상 파일이 없습니다.

5. 실행 위치 — 맥북 vs 윈도우 PC

민수님 직관("서버처럼 쓰는 윈도우에 던져두면 알아서 끝나 있을 것")은 일반적으로는 맞지만, 이 작업에서는 반대입니다.

맥북 24시간 윈도우 PC
칩 Apple M5 Pro / 48GB AMD Ryzen 5 2400G (2018, 4코어) / 14GB
GPU 가속 Metal 사용 CUDA 없음. Vega 11 내장그래픽은 whisper에 무의미
실측 전사 속도 37배 실시간 (16분 → 26초) 미실측. CPU 전용이라 자릿수 단위로 느림
86시간 전사 예상 2.3시간 며칠 단위

맥북에서 2.3시간이면 끝납니다. 백그라운드로 돌리면 되고, whisper.cpp는 스레드 수를 제한할 수 있어(-t 6) 민수님이 쓰시는 데 방해되지 않게 조절 가능합니다.

윈도우 PC를 안 쓴다는 뜻은 아닙니다

역할을 나누는 게 맞습니다.

  • 윈도우 PC: 오디오 다운로드(CPU를 안 씀, 시간만 걸림), 야간 스케줄, 원본 보관. 이미 라이브 재업로드 자동화가 거기 살고 있어 자연스럽습니다
  • 맥북: 전사(GPU 가속이 결정적)

다만 다운로드도 16분 영상에 3초라 844편이 1~2시간이면 끝납니다. 굳이 나눌 실익이 크지 않으면 맥에서 통으로 돌리는 게 단순합니다.

6. 확장프로그램 활용

서버 엔진을 그대로 씁니다. 이미 필요한 게 다 있습니다.

이미 있는 것 파일
yt-dlp 래핑 + 쿠키 자동 감지 + 403 재시도 server/server.js
PLAUD 업로드 전 과정 server/plaud/extension-upload.js
5시간 자동 분할 / 전사본 병합 plaud/audio-split.js, plaud/transcript-merge.js
실패 큐 + 재다운로드 없는 재시도 POST /plaud/retry-failed
인사이트 회수 plaud/insight-processor.sh

추가할 것은 두 개뿐입니다.

  1. 배치 러너 — 영상 URL 목록을 받아 POST /plaud/send에 순차로 넣고, 실패분을 재시도 큐로 넘기는 스크립트
  2. 로컬 whisper 분기 — 쇼츠·일반영상은 PLAUD를 거치지 않고 bestaudio → 16kHz 모노 opus → whisper-cli로 바로 전사하는 경로

확장프로그램 UI는 쓰지 않습니다. 영상 하나씩 버튼 클릭 방식이라 844편에는 맞지 않습니다.
UI가 아니라 엔진 재사용입니다.
