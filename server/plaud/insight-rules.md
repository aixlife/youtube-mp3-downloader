# PLAUD 영상 인사이트 — 분류·정리·제안 규칙 (v0.1 초안)

> 이 파일이 스키마다. 후처리 AI는 매 실행마다 이 파일 전체를 읽고 따른다.
> 규칙은 실사용 피드백으로 계속 발전시킨다 — 민수의 분류 정정·제안 기각·"이건 좋았다" 한마디가 들어올 때마다 아래 '판례' 섹션에 누적하고, 판례가 5건 쌓이면 본문 규칙으로 승격을 제안한다.
> 지표는 하나만 본다: **내 강의·사업·채널·제품에 실제로 쓰인 노트 수** (분류 체계 자체에 고집 금지 — 2026-07-16 설계 결정).

## 0. 목적

민수가 유튜브에서 PLAUD 버튼을 누르는 이유는 하나 — 비즈니스·교육에 도움되는 인사이트를 모으기 위해서다. 따라서 산출물은 "요약 보관"이 아니라 **지금 민수 상황에 꽂히는 적용안 + 다시 꺼내 쓸 수 있는 정리**여야 한다.

## 1. 입력

- 전사 원문: PLAUD CLI가 저장한 transcript (화자 라벨 포함)
- 현재 상황 팩: `situation-pack.md` (활성 프로젝트·이번 주 우선순위 — 세션 캡처 시 자동 갱신, 없으면 memory MEMORY.md 인덱스로 대체)
- 이 규칙 파일 전체

## 2. 분류 (5축 + 자산 태그)

| 카테고리 | 판정 기준 |
|---|---|
| 수익화사례 | 특정인이 AI/자동화로 돈 번 구체 경로·숫자가 있다 |
| 실행기법 | 따라할 수 있는 도구·프롬프트·워크플로우가 단계로 나온다 |
| 오퍼공식 | 가격·카피·상세페이지·판매 구조의 공식/템플릿이 있다 |
| 콘텐츠전략 | 채널 성장·기획·편집·알고리즘 노하우다 |
| 세계관 | 산업 방향·노동의 미래 등 강의 오프닝/스레드 글감용 큰 그림 |

- 자산 태그(복수): `강의` `회사` `채널` `제품` `컨설팅`
- 확신도: 상/중/하 — '하'는 `insights/videos/unsorted/`로 (민수 판정 대기, 억지 분류 금지)

## 3. 노트 포맷 (Obsidian: `insights/videos/YYYY-MM-DD-제목.md`)

```markdown
---
category: <5축 중 1>
assets: [강의, 채널]
confidence: 상|중|하
source: <영상 제목 / PLAUD id>
status: active   # active | done | archived
---

## 전체 요약 (5줄 이내 — 민수 상황 렌즈로)
그냥 영상 요약이 아니라 "민수에게 이 영상이 왜 의미 있는가"의 렌즈로 쓴다.

## 핵심 문장 (3-5개)
- "원문 인용" — 왜 이 문장이 민수에게 중요한지 한 줄
(따라 말하고 싶은 문장, 강의에서 인용할 문장, 반박하고 싶은 문장 모두 후보)

## 지금 제안 (1 액션 + 1 질문)
- 액션: [어느 프로젝트 어느 지점에] — 첫 단계는 오늘 10분짜리로 쪼갠다
- 질문: 실행이 아니라 방향을 자극하는 생각거리 1개

## 대기 제안 (2-3개, 한 줄씩)
지금 제안이 실행/기각되면 여기서 하나를 승격한다. 영상 하나에 액션 하나만 나올 리 없다 — 나머지를 버리지 말고 대기열에 보존.

## 실행 로그
- YYYY-MM-DD · 제안 v1 · 실행함/기각/보류 · 배운 것 한 줄
```

## 4. 적용 제안 생성 규칙

1. 상황 팩을 먼저 읽고, 제안은 반드시 실존 프로젝트·실존 산출물 지점을 명시한다. "비즈니스에 적용해보세요" 수준의 일반론이면 제안을 생성하지 말 것.
2. 표면에는 항상 **1 액션 + 1 질문**만. 나머지 후보는 대기 제안으로.
3. 확신도 '하'면 액션 없이 질문만.
4. 승격 루프: 민수가 실행 로그에 결과를 남기거나 "다음 제안"이라고 하면, 대기열에서 (a) 직전 실행의 배움을 반영해 (b) 현 상황 팩 기준으로 재평가 후 1개를 승격한다. 대기열이 비면 노트 status를 done으로.
5. 제안 실패(기각·불발)는 삭제하지 말고 실행 로그에 남긴다 — 판례의 원료다.

## 5. 판례 (분류 정정·제안 피드백 누적 — 최신이 위)

- 2026-07-17 · 첫 실사용 무인 완주 2건(세일즈콜 $1000 클로징·바이브코딩 지도 1부) 품질 검증 통과: 분류(수익화사례/실행기법)·1액션+1질문·오늘 10분 스코핑·실존 산출물 특정(AIMAX 컨설팅 교보재·패캠 1강 오프닝) 모두 규칙 부합. 세일즈콜 건은 "돈 경로·숫자 중심 → 수익화사례 우선" 판례가 실제 반영된 첫 사례. 확신도 상 2건 모두 실존 지점이 특정돼 정당 — 게이트는 유지하되 계속 감시.
- 2026-07-17 · SLUG에 날짜를 포함해 출력한 사례(바이브코딩 1부) — 스크립트가 붙이는 날짜와 중복되고 40자 컷과 겹쳐 파일명이 파손됨. SLUG는 날짜 없이 내용 슬러그만 (프롬프트에 명시 + 스크립트 이중 방어 완료).
- 2026-07-17 · 소급 51건 중 확신도 '하' 0건(상 45·중 5) — 후처리기가 확신도를 과신하는 경향. '민수의 어느 실존 산출물에 꽂히는지 특정 못 하면 하'로 기준을 엄격 적용할 것. unsorted가 계속 0이면 이 게이트는 장식이다.
- 2026-07-17 · 소급 분포: 실행기법 38 / 세계관 6 / 수익화사례 3 / 콘텐츠전략 2 / 오퍼공식 1 — 실행기법 편중은 다운로드 동기와 일치하나, 수익화사례로 볼 여지가 있는 영상이 실행기법으로 흡수되는 경향 관찰. 돈 번 경로·숫자가 중심이면 수익화사례 우선.

## 6. 소급 캘리브레이션 노트

기존 `~/Downloads/PlaudTranscripts` 참고 영상 ~50건을 이 규칙으로 소급 처리해 초기 판례를 만든다. 소급분은 "지금 제안"의 시효가 지났을 수 있으므로 상황 팩 기준으로 재평가하고, 이미 실행된 것으로 보이면 실행 로그에 추정 표기.
